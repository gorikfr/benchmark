How to interpret these results

Use this dashboard to compare models on the same machine, server settings, prompt, and experiment. A faster model is not automatically a better model: first check whether it gives acceptable answers, then choose the speed profile that matches your workload.

What do “gen” and “long prompt” mean?

BenchmarkWhat it stressesHow to read it
genTwo short, warmed-up requests that generate an answer.Mostly reflects output/decode speed for an ordinary interactive response.
long promptOne request with roughly 2,800 input tokens before generating a shorter answer.Shows how the model behaves when it must first process a large context, such as a document or RAG prompt.

Metric glossary

MetricBetterMeaning
gen tok/sHigherOutput tokens generated per second after the first token. This is the main “how fast does text stream?” metric.
prefill tok/sHigherDirectional estimate of how quickly the input prompt is processed, calculated from prompt tokens and TTFT. It is useful for comparing runs, but TTFT also includes scheduling and other request overhead.
TTFTLowerTime to first token: how long you wait before any answer appears. It includes request, queueing, prompt-processing, and server overhead—not just model computation.
total (s)LowerTotal time until the response finishes. It depends heavily on the number of output tokens, so compare it only when prompts and output limits are comparable.
IQ / task scoreHigherAccuracy on the fixed machine-scored tasks. Request failures are excluded from the accuracy denominator and shown separately; a missing score is not a zero.

Which metrics matter most?

For interactive chat: prioritize task quality, then TTFT for responsiveness and gen tok/s for smooth streaming.

For long documents or RAG: prioritize task quality, then TTFT and the long-prompt row’s prefill tok/s.

For batch jobs: prioritize task quality and gen tok/s; use total time when every model produces similarly sized outputs.

The combined ranking gives quality and speed equal weight after normalizing speed across the selected experiment. Treat it as a convenience summary, not a universal truth. Compare averages across several runs, and do not compare results from different experiment IDs unless the hardware and server configuration are equivalent.
